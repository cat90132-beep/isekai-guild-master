独立机器人安装包为 `astrbot_plugin_guild_replay.zip`，不依赖 GuanpengNet。导入AstrBot后配置回放地址，安装 Chrome/Chromium/Edge。`/g查询` 默认以图片显示今天的对局与获胜者，`/g胜率` 图片显示开局行动顺位及角色胜率；指定日期和翻页见插件README。

更新服务时保留已有 `replays/` 和自定义 `server_config.json`。新包构建修订号为 `20261015-3.2.0-lobby-cleanup`。源码和部署包已更新，公网服务需由部署端在对局结束后替换并重启。

客户端连接顺序：服务器 → 房间大厅 → 创建 / 加入 / 观战。默认服务器为 `guanpeng666.cn:6677`；设置或连接页面可修改地址和端口。客户端不再启动本地监听服务。

## 配置文件 server_config.json

与 `server.py` 同目录的 `server_config.json` 控制三个服务的开关与端口，改完重启即可生效。命令行参数会覆盖这里的设置。

```json
{
  "host": "0.0.0.0",
  "game_port": 6677,
  "replay_port": 6767,
  "site_port": 6680,
  "record_replays": true,
  "enable_replay": true,
  "enable_site": true
}
```

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `0.0.0.0` | 监听地址。只想本机访问可改为 `127.0.0.1` |
| `game_port` | `6677` | 游戏 TCP 端口 |
| `replay_port` | `6767` | 对局回放网站端口 |
| `site_port` | `6680` | 对战器网站端口。**不要用 6665–6669**（IRC 保留段，浏览器会报 `ERR_UNSAFE_PORT`） |
| `record_replays` | `true` | 是否把每局写入 `replays/`。关闭后不再产生新回放文件，已有的仍可浏览 |
| `enable_replay` | `true` | 是否开启回放网站（HTTP）。关闭后该端口不监听 |
| `enable_site` | `true` | 是否开启对战器网站（HTTP）。关闭后该端口不监听 |

行为细节：

- 文件不存在、JSON 有语法错误、类型不对（例如 `"game_port": "abc"`）时**不会崩溃**：启动日志会给出警告，并对该项回退到内置默认值；布尔项必须是 `true` / `false`。
- 额外未知的键会被忽略，便于保留注释或未来扩展。
- `enable_site` 为 `false` 时对战器网站不启动，`enable_replay` 为 `false` 时回放网站不启动（游戏本体 6677 始终提供）。若同时关闭对战器网站，`--site-port` 的占用也就释放了。
- 对战器网站显示的端口与回放链接来自实际运行参数：即使改了端口，页面上的地址也会同步正确；回放网站被关闭时页面会显示「回放网站已关闭」。
- 回放录制与回放网站是两件事：`record_replays` 管写入，`enable_replay` 管浏览器查看。

对应的命令行开关：`--config 路径`、`--host`、`--port`、`--web-port`、`--site-port`、`--no-replay`、`--no-site`、`--no-record`、`--replay-dir`、`--site-dir`、`--download-dir`、`--max-rooms`。

只跑游戏、不开放任何网页：

```sh
python3 server.py --no-site --no-replay
```

## 快速启动

安装 Python 3.9 或更新版本。解压 `deployment/guild-server.zip`，进入其中的 `guild-server` 目录：

```sh
python3 server.py --host 0.0.0.0 --port 6677
```

Windows 使用 `python server.py --host 0.0.0.0 --port 6677`。

这是纯 Python 标准库服务器，不需要 Ren'Py、桌面环境、图片、音频或 pip 依赖。出现 `Guild server listening on 0.0.0.0:6677` 后保持进程运行。同一进程还会自动启动回放网站（6767）与对战器网站（6680），需要时一并放行这两个 TCP 端口。

将 `guanpeng666.cn` 的 DNS A 记录指向服务器的公网 IPv4。在云安全组和系统防火墙放行 **TCP 6677**。这是原生 TCP 游戏协议，不是网页，不能直接套用 HTTP 反向代理；若域名使用仅代理 HTTP 的 CDN，请使用 DNS-only 解析。部署在内网时还需映射 TCP 6677 到运行服务器的设备。

## Windows 部署

1. 确认服务器已安装 Python 3.9 或更高版本，在 PowerShell 中执行 `python --version` 检查。
2. 将 ZIP 完整解压，进入包含 `server.py` 的 `guild-server` 文件夹。在该文件夹打开 PowerShell，运行：

   ```powershell
   python server.py
   ```

   如果系统使用 Python 启动器，也可运行 `py -3 server.py`。
3. 在 Windows 防火墙和云服务器安全组中放行入站 TCP 6677、6767、6680，分别供游戏、回放和对战器网站使用。关闭对应网站时无需开放其端口。
4. 看到监听成功的日志后保持该窗口运行。客户端填写服务器公网 IP 与端口 6677；浏览器访问 `http://服务器公网IP:6680` 查看网站，访问 `http://服务器公网IP:6767` 查看回放。按 Ctrl+C 停止服务；关闭启动窗口或注销当前会话可能停止前台服务。

从旧版更新时先备份旧目录，等对局结束后停止旧进程，再部署新包。保留原有 `replays/`、自定义 `server_config.json` 和 `downloads/` 中的客户端安装包，避免覆盖或丢失。配置中的端口若有修改，以实际配置为准。客户端也需要更新至包含本次轮抽功能的版本。

## Linux 长期运行

把解压后的目录放在 `/opt/guild-server`。附带的 `guild-server.service` 使用 `/usr/bin/python3` 和 `guild` 账户；若你的路径不同，请修改文件。

```sh
sudo useradd --system --no-create-home --shell /usr/sbin/nologin guild
sudo cp guild-server.service /etc/systemd/system/guild-server.service
sudo systemctl daemon-reload
sudo systemctl enable --now guild-server
sudo systemctl status guild-server
journalctl -u guild-server -f
```

服务以非管理员账户运行，游戏文件只需可读。

## 房间与重连

- 同一服务器可托管多个房间，默认最多 32 间。`--max-rooms 64` 可修改房间上限；传输层同时连接上限为 64（玩家、观战与大厅连接合计）。
- 房间支持 2–5 人。先由各玩家准备、房主开始，然后才随机发角色候选。每人从 1–5 张候选中选一名及可用黑/白版本；候选张数由房主设置。全部选完后进入正式对局。候选只发送给本人，各玩家的候选人物不重复。
- 创建房间可禁用角色，同一角色的黑白版本一起禁用。剩余人物需足够供人数与候选张数共同使用；不足时创建或开始会被拒绝。五人各抽五张需要 25 名人物，当前 23 人池应改为每人最多四张。
- 房主可设置地图、事件包及额外规则。五人使用大地图；禁止区域限 1–3 人。开启「迷宫大变动」会自动开启变动板块。离线单人直接运行本地规则，不建立 TCP 连接，也不需要此服务器。
- 房间还有玩家或观战者在线时，房主离开不会关闭房间。断线后可点击重连，也可重新打开游戏，以原昵称和房间密码加入原房间。
- 名字在房间内忽略大小写比较；只能恢复离线席位，不能冒用同名接管在线玩家。程序内断线优先使用临时重连令牌。
- 没有账户密码验证；知道昵称和房间密码的人可以认领离线席位。这是按名字重连的取舍，建议熟人对局设置房间密码，不要使用其他服务的重要密码。当前 TCP 通信未加密，不适合不可信网络上的敏感数据传输。
- 当前需要行动的玩家断线时显示「断线」，并按房间的断线宽限设置等待重连，默认 30 秒，可在 1–3600 秒间修改。超时后自动完成必要选择并本季闭店。该宽限独立于可选的行动倒计时。
- 房主可以踢出其他玩家。开局前释放席位；对局中保留其公开状态并自动结算、闭店。被踢者的令牌失效，同昵称不能重新进入原房间。观战仍只能查看公开内容。
- 新增强制大地图及不按人数禁用秘药格的房间开关。炼金秘药仍依赖炼金工房模块。
- 所有玩家离开或断开后，已开始的房间会保留一个断线宽限期（默认30秒），期满无人重连就自动销毁；未开始的房间立即清理。观战者不会阻止清理，观战者加入或离开也不会重置宽限计时。房间销毁后，观战者保持服务器连接并返回大厅，大厅房间列表同步刷新。任一玩家在宽限内回来则取消清理。已销毁房间无法重连，客户端会回到大厅。
- 2026-10-09 房间清理修订：服务器启用 TCP 保活，连接空闲 30 秒后由系统每 10 秒探测一次；探测失败后断开失效连接，再按房间的重连宽限清理。具体断线判定耗时取决于操作系统。正常在线但没有操作的玩家不会因此被踢出，也不需要更新客户端。定时销毁房间后会主动刷新所有大厅连接的房间列表。

- 没有可恢复的本地对局存档。服务器重启会清空所有房间，但公开回放会保留在磁盘。旧启动参数 `--idle-hours` 仅为兼容保留，不再延长房间寿命。不要在对局中途重启服务。

## 更新

客户端和服务器必须同步更新到本次 3.2.0 修订版（含开局轮抽）。停止旧服务后，完整替换本压缩包中的 Python 文件、素材索引 JSON、`replay_web/` 与 `site/`，然后重新启动；客户端也必须完全退出后重开。更新规则后，重新运行 `python tools/build_release.py` 生成部署压缩包。选择所有对局结束的时机更新。`deployment/guild-server.zip`、根目录 `server.zip` 和下载目录中的服务器包同步为同一最新版。

3.2.0 客户端在进入房间列表前发送版本信息。旧客户端连接新版服务器时，服务器回复「过期的客户端，请更新」并断开连接；玩家需要更新客户端后重新连接。

包内 `BUILD_INFO.json` 记录版本、UTC 构建时间和每个发布文件的 SHA-256。源码文件保留自身修改时间，不能单凭某个旧文件的时间判断整包版本；用构建清单核对内容。

本仓库只生成部署文件，不会自动连接或修改你的公网服务器。

如果旧房间仍显示有人在线，可在确认没有进行中的对局后停止服务，部署最新 `deployment/guild-server.zip` 并重新启动。房间仅存在于内存，重启会清空旧房间；保留原有 `replays/` 和自定义配置。无需删除回放文件。修订包的 `BUILD_INFO.json` 中 `revision` 为 `20261009-3.2.0-room-cleanup`。


## 对局回放网站（6767）

同一个 `server.py` 进程同时提供 TCP 6677 游戏服务和 HTTP 6767 回放网站。浏览器访问 `http://服务器地址:6767`。云安全组、系统防火墙与端口映射需另外放行 TCP 6767。

- 从对局开始记录初始状态、每次成功行动、每个效果选择和资源支付步骤；无效请求不产生回放步骤。
- 网站提供对局列表、六角地图、公会资源、操作记录、上一步/下一步、自动播放与可拖动进度条。
- 网站按五席布局并排显示最多 5 位公会长，每位显示自己的看板娘立绘、金币/力量/秘药与三项产能、手牌、保留情报、已打出事件、迷宫板块、私人王权、宝物、标记与发展项目。
- 卡牌与板块以缩略图显示，点击任意卡牌（含王权卡）或板块即可放大查看原图；按 `Esc`、点击背景或右上角 × 关闭。
- **回放是完整视角录像**：每一席的手牌、保留情报、私人王权、私人板块与未探索情报都会写入磁盘，用于复盘。因此进行中的对局也会立刻出现在 6767 网站上，务必只把该端口开放给可信网络；实时观战接口（TCP 6677）仍是公开视角，不泄露他人手牌。
- 回放默认存放在服务端目录的 `replays/`，进程重启或房间解散不会删除。进度从 1 开始，第一步是对局初始状态。它用于复盘，不用于恢复对局。
- `--web-port 6767` 可修改网页端口；`--replay-dir /path/to/replays` 可修改保存目录。运行账户必须有该目录的写权限。
- systemd 示例使用 `StateDirectory=guild-server`，把回放保存在 `/var/lib/guild-server/replays`，兼容附带的只读系统保护设置。
- 更新时完整替换 Python 文件及 `replay_web/` 文件夹，保留回放目录。回放没有自动清理期限，可按磁盘容量定期备份和归档。
- 网站的立绘与卡牌缩略图是离线生成的静态资源（`replay_web/portraits/`、`replay_web/cards/`），这样部署端不需要整套游戏图片。替换角色或卡牌素材后，用 SDK 自带解释器重新生成：`lib\py3-windows-x86_64\python.exe tools\build_replay_assets.py`，再运行 `python tools/build_release.py` 打包。


## 对战器网站（6680）

同一个 `server.py` 进程还会在 **HTTP 6680** 提供对战器网站：游戏介绍、玩法特色、截图、看板娘一览与加群下载提示。浏览器访问 `http://服务器地址:6680`。需要另行放行 TCP 6680。

> 不要用 6667：6665–6669 属于 IRC 保留端口，Chrome / Edge / Firefox 会直接以 `ERR_UNSAFE_PORT` 拒绝访问。默认端口已选为同段的 6680，可用 `--site-port` 修改。

- 页面内容与文案在 `site/`：`index.html`、`style.css`、`app.js`、`favicon.svg`，站点信息（版本、口号、服务器地址与端口）在 `site/site.json`。
- 网站不再提供客户端或服务器文件下载。所有下载入口点击后提示「加群2155021664下载」；原 `/download/` 链接返回 HTTP 410 和同样的群号提示。
- `/api/site` 不再列出本地文件，下载列表固定为空。`downloads/` 中已有文件保留，但不会通过网站对外提供。
- 看板娘立绘直接复用回放用的 `replay_web/portraits/`；对战器网站截图是离线生成的 `site/shots/*.jpg`（由 `python tools/build_site_assets.py` 从 `qa/` 重新生成）。
- 对战器网站、回放站与游戏共用一个进程；`--site-port` 和 `--site-dir` 可调整端口与页面目录。`--download-dir` 仅为旧部署配置兼容保留，不恢复下载服务。
- 机器人状态接口见 [API.md](API.md)。
